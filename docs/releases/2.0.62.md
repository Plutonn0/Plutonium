# Plutonium 2.0.62 — Readability and error handling

This maintenance release expands dense code and standardizes formatting across the Java client, Fabric integration, C# launcher, moderation JavaScript, tests and PowerShell tooling. Existing module behavior, settings, UI layout and authentication rules are retained.

Error handling now preserves the useful failure when temporary cleanup or database rollback also fails. Locked staging files do not hide cancellation or checksum failures; unsuccessful mod recovery retains its copies and both causes. Invalid saved HUD/sidebar entries keep their existing fallback while valid settings continue loading. Client diagnostics are rate-limited and omit private values. Launcher reports include nested failures and redact additional identity tokens and device codes.

The moderation source uses a shared transaction helper and handles idle database connection errors without logging SQL or credentials. The updated API source is included in the handoff archive; Vercel deployment is separate from this GitHub release.

Also includes the pending Fake Pay amount fix: K, M and B are the only supported suffixes and are displayed uppercase. Plain numbers remain valid; malformed amounts show an error. The dollar sign stays green (`#00FF00`).

Both client profiles and the Windows launcher are versioned 2.0.62.

Validation: 171 automated tests passed (47 client, 86 launcher, 38 moderation); three optional live Modrinth tests were skipped. Standalone and Fabric in-game smoke checks both passed. Formatting-only changes were checked for equivalent Java bytecode, C# syntax tokens, JavaScript syntax trees and PowerShell tokens before the error-handling edits.
