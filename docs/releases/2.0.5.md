# Plutonium 2.0.5 — SusChunk block-change detection

SusChunk now highlights blocks placed, removed or replaced while this client observes the world, including empty spaces left by mining underground. It no longer relies on other players moving nearby. Red block highlights stay aligned to world coordinates, with an optional chunk border.

Right-click SusChunk for Minimum changed blocks (default 1), render distance, border visibility and color. The old movement threshold is replaced, so saved movement settings cannot silently hide block changes. Observations are bounded and session-local, collected even before enabling the overlay, and cleared when the world/dimension changes. Restoring a block to its observed original type removes the mark. Door/redstone state changes and fluid-only updates are excluded.

This is evidence of observed block changes, not proof of who caused them. Explosions and natural block changes can also be recorded. It cannot reconstruct a pre-existing mined area on a first visit without an earlier baseline. No world seed or server history is guessed.

Validation: 37 Java tests and 79 launcher tests passed (3 optional live Modrinth tests skipped). Placement, removal and restoration hooks passed in both standalone and Fabric in isolated game worlds. The offline integration fixtures use a test-only service configuration; the Fabric fixture loads the unchanged bundled assets as a resource pack. Both shipped clients retain the production moderation endpoint.
